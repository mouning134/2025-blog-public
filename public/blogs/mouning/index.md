# 傻瓜都能学会的vibe coding


工作流程（简洁版）：
1.一句话我们想要什么
2.主要功能和要求
3.第一版不做什么
4.不明白的AI问清楚，多开一个AI额外解答问题，节省上下文和积分


# 一.写需求提示词



```markdown
我想做一个...（项目）（你自己想做的内容或者app之类的）
项目的功能+需求
这个项目只在本地运行，数据保存在本地，不需要登陆或者联网，数据库部署和手机端
现在先不要写代码或者创建项目
请先检查需求是否缺少必须确认的内容，如果有，问我个问题，一次只问一个；如果没有，请用普通人的语言复述需求，并整理第一版应该完成和暂时不做的内容，待我确认。
```


# 二.页面结构和交互设计



```markdown
确认，进入页面结构和交互设计
```



# 三.产品需求文档



```markdown
产品需求文档
请把刚才已确认的内容整理并保存PRD.md，作为后续开发依据
 
保留：目标和使用场景
整个页面设计和结构（导航）
每个模块块的用途
各个模块之间的关系
本地数据文件、备份和恢复要求
第一版必完成的内容（功能）
第一版暂时不做的内容（功能）
可以实际检查的验收标准	
```

解决：Agent对话长度过长，很多信息可能被遗漏，有PRD文档可以通过文档进行开发



# 四.开发计划



```markdown
   4.开发计划
根据当前的PRD.md，请给出一份详细，可以执行的开发计划
 
请根据开发计划开始开发
按照计划顺序一步一步连续完成。每完成一个阶段，都要添加并运行对应的有效测试。测试失败就先定位并修复，通过以后再继续下一阶段
 
持续执行，直到开发计划全部完成
 
不允许通过删除测试、跳进测试或降低标准让测试通过
 
全部完成后 运行所有测试。
```


# 五。第一版验收


查询是否有改进的地方（UI设计，功能按钮）

提出问题1，2，3，4，5...让AI改进



# 六.使用git代码存档



让AI使用git存档代码（版本更新后，存档之前的版本）


```markdown

git的安装：
检查本地环境并安装git

初始化git仓库：
（请在当前项目中初始化git仓库）

commit提交来存档代码：
（创建第一次git提交）
```

为了避免上下文过长的问题，也可以让AI总结这次任务

prompt：

```markdown
请你总结这次任务的执行进展和问题的确保，下次回来确保能接上
```
